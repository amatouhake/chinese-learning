## Audio sources

### audio-cmn

- Source: <https://github.com/hugolpz/audio-cmn>
- Role: Mandarin word recordings used for the pronunciation listening and compare steps
- Source revision: `ff9ed3d0c631195bd2c06f39450f3264c7124040`
- Imported path: `64k/hsk/cmn-{Hanzi}.mp3`
- License: Creative Commons Attribution-ShareAlike (CC BY-SA), as declared by the source
- Attribution in the source: Yue Tan; collected for the Spoken Wikipedia Corpora (SWAC)

The corpus is not committed here. The pronunciation importer reads a separately pinned checkout,
verifies each contributing worktree file against the Git blob at the revision above, and copies only
exactly mapped recordings to ignored `.generated/public/media/` for local delivery. The generated
report retains the source commits and explicit recovered, ambiguous, and missing issue details.
Each D1 media record retains the audio source name, license, attribution, source path, commit, byte
length, digest, and stable content identity. Those staged audio files retain CC BY-SA and are not
relicensed by the application's MIT license.

### Exact-reading metadata

- Source: <https://fsi-languages.yojik.eu/audiocollections/detailled/cmn-caen-tan/flac/index.tags.txt>
- Collection/readme: <https://fsi-languages.yojik.eu/audiocollections/detailled/cmn-caen-tan/readme.txt>
- Role: pronunciation evidence used only to recover an exact audio-to-reading relationship
- Source identity: `shtooka:cmn-caen-tan`
- Source artifact SHA-256:
  `b6dae2557ee6245d83bb12de1b4ea0ad3b10da9fc25e1e55b206b0c305cd2511`
- Checked-in normalized snapshot: `data/pronunciation/shtooka-cmn-caen-tan.json`
- Snapshot SHA-256:
  `b3cb696adef27aa132aa9e219cd619a0baef6188b720ffa779d72e2813ea899b`
- Trusted fields: `SWAC_TEXT` and `SWAC_PRON_PHON`

The snapshot is generated by `scripts/extract-pronunciation-metadata.ts` from the source index,
the pinned vocabulary revision, and the pinned `audio-cmn` tree. Import execution uses only this
checked-in snapshot and performs no network fetch. The metadata source is provenance for the
mapping rationale; it does not replace or relicense the `audio-cmn` bytes. The old
`exact_hanzi_filename_single_active_reading` basis remains valid for single-reading lexemes. The
new `exact_source_pronunciation_active_reading` basis is used only when the source pronunciation
normalizes to one active canonical reading; zero or multiple matches remain unresolved.
